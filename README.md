Сервис учёта занятий репетитора

Учебный проект по системному анализу, идея основана на моём опыте работы репетитором по математике: расписание, переносы и отмены занятий, учёт оплат и долгов сейчас ведутся вручную, что не всегда удобно ввиду обилия информации. Проект описывает, как такой сервис мог бы работать.

Само приложение не реализовано, в проекте только аналитика и база данных, а все данные вымышленные.

Что внутри:

- требования (функциональные и нефункциональные)
- модель данных: ER-диаграмма и скрипты PostgreSQL
- 14 SQL-запросов с результатами
- процесс «занятие => оплата» в BPMN
- сценарий переноса занятия в виде диаграммы последовательности
- описание API в формате OpenAPI
- проверка нефункциональных требований на тестовых данных

Структура проекта:

```
docs/
  requirements.md        требования
  query_results.md       SQL-запросы и их результаты
  sequence_reschedule.md диаграмма последовательности (перенос занятия)
  nfr_checks.md          проверка нефункциональных требований
er/
  er_diagram.png         ER-диаграмма
bpmn/
  tutor_service.bpmn     процесс в BPMN
  tutor_service.png      картинка процесса
sql/
  schema.sql             создание таблиц
  seed.sql               вымышленные тестовые данные
  queries.sql            SQL-запросы
api/
  openapi.yaml           описание API
```

Основные решения:

1) В базе шесть таблиц: 'parents', 'students', 'services', 'lessons', 'reschedules', 'payments'.
2) У занятия пока нет статуса ('null'), затем ему ставится один из итоговых: «Проведено», «Перенесено» или «Отменено».
3) Запись об оплате создаётся, когда занятию поставлен итоговый статус (когда «Проведено» или «Отменено»), отменённое занятие остаётся «Не оплачено», так видны потери на отменах.
4) Долг ученика - это неоплаченные записи по проведённым занятиям.
5) Перенос оформляется одной транзакцией: создаётся новое занятие, старое получает статус «Перенесено», перенос записывается в историю.
6) В базе хранятся только псевдоним и контакт для обеспечения минимума персональных данных.

Как запустить базу:

1. Создать пустую базу данных в PostgreSQL.
2. Выполнить 'sql/schema.sql' - создание таблиц.
3. Выполнить 'sql/seed.sql' - заполнение таблиц тестовыми данными.
4. Запросы из 'sql/queries.sql' выполняются на этих данных, результаты лежат в 'docs/query_results.md'.

Скрипты проверялись в PostgreSQL через DBeaver.

Инструменты:

PostgreSQL, DBeaver, dbdiagram.io (ER-диаграмма), bpmn.io (BPMN), Mermaid (диаграмма последовательности), OpenAPI 3.0.3, Markdown.
