Sequence-диаграмма переноса занятия

Сценарий из US-2: Ученик или родитель просит перенести занятие, репетитор решает, принять ли перенос, а система фиксирует результат в базе данных. Решение принимает репетитор вне системы, поэтому при отказе в БД ничего не меняется.

```mermaid
sequenceDiagram
    actor Клиент as Ученик / родитель
    actor Репетитор
    participant Система as Приложение (API)
    participant БД as БД (PostgreSQL)

    Клиент->>Репетитор: Просит перенести занятие, предлагает новое время
    Репетитор->>Репетитор: Решает, принять ли перенос

    alt Перенос принят
        Репетитор->>Система: POST /reschedules (занятие, новое время, кто просил)
        Система->>БД: Проверить пересечения нового времени
        БД-->>Система: Результат проверки

        alt Время занято
            Система-->>Репетитор: 409 Conflict
            Репетитор->>Клиент: Предлагает другое время
        else Время свободно
            Система->>БД: BEGIN
            Система->>БД: INSERT нового занятия
            Система->>БД: UPDATE старого занятия, статус «Перенесено»
            Система->>БД: INSERT записи в reschedules
            Система->>БД: COMMIT
            БД-->>Система: OK
            Система-->>Репетитор: 201 Created (id нового занятия)
            Репетитор->>Клиент: Сообщает новое время
        end
    else Перенос отклонён
        Репетитор->>Клиент: Сообщает об отказе
        Note over Репетитор,БД: В системе ничего не меняется
    end
```

Пояснения:

1) Приложение (API) - целевое приложение между репетитором и базой данных, которое будет предоставлять методы из 'api/openapi.yaml'. В учебном проекте оно не реализовано: его роль выполняют SQL-команды, которые репетитор запускает в клиенте БД. Диаграмма показывает, как взаимодействие выглядело бы в готовом сервисе.
2) Проверка пересечений выполняется запросом к 'lessons' (FR-3). Схема БД пересечения не запрещает, поэтому проверка нужна до записи.
3) Три записи в одной транзакции (BEGIN … COMMIT): новое занятие, смена статуса старого, запись о переносе. Либо проходят все три, либо ни одна.
